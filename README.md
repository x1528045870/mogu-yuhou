# 蘑菇·雨后

雨后，蘑菇在说不准的时间冒出来。每场雨只带回 1 到 3 朵：从你喂过的东西里长出来的，偶尔还有一朵迷路的野蘑菇。

这是 v0 原型：它不依赖任何一台电脑，全靠 GitHub Actions 自己跑；**原型阶段不连任何 AI API，不花钱**，蘑菇从一个事先采好、链接都核实过的蘑菇池（`pool.yaml`）里带。

## 它怎么工作

1. GitHub Actions **每小时看一次天**，按概率决定下不下雨。只在醒着的时段下；两场之间至少隔 4 小时；一天最多两场；太久没下，概率会提高。
2. 下雨了，就从**蘑菇池**里挑 1–3 朵：带过的不再带；该带野蘑菇时带一朵；一周最多一朵松茸；同一场尽量不重复品种；你说过「好吃 / 还想要」的那一类更容易冒，「难吃 / 别再带」的那一类更难冒。
3. 以后想让它真的出门现采，把 `config.yaml` 的 `source` 改成 `claude`：Claude 会按喂过的东西联网搜索，而且链接必须原样出现在这次的搜索结果里，凭记忆编的一律扔掉。
4. **送到你手上**：ntfy、微信（Server酱）、邮件。哪个渠道配了密钥就发哪个。推送只预告「冒了几朵、什么品种」，不剧透内容，只有一个「去采蘑菇」的入口。
5. **到网页上采**：雨停了，湿土里长出几朵，只看得到品种。**按住**一朵大约 0.7 秒才采得下来（松手就取消；键盘按回车），采下的那朵飞进笔记，变成一张编了号的标本卡。采完就到底：「都采完了，下一场雨说不准什么时候来」。没有倒计时，也没有天气预报。
   网页还有一张最近五周的雨历，和按品种分的标本柜。
6. 这场雨记进 `docs/data/rains.json`，网页读它来显示篮子和图鉴。

## 回信箱：在网页上直接反馈和喂

网页上的「好吃 / 难吃 / 还想要 / 别再带」和「喂一口」，点一下就会把一条小消息投进 ntfy 的一个**反馈主题**；每小时看天时，Actions 把它们拉回来处理。不用另搭后台。

- 反馈主题默认是推送主题后面加 `-fb`，也可以单独配 `FEEDBACK_TOPIC`。
- 主题名就是钥匙，只放在发给你的推送链接里（`#k=…`）。从推送点进网页，钥匙会存在这台设备的浏览器里，地址栏随即抹掉。所以别把带 `#k=` 的链接转给别人。
- 别人直接打开网页只能看；没有钥匙的设备，反馈按钮会退回到「开一个 GitHub Issue」。
- 为了第一周复盘，它会记两个数：每场雨你第一次来采的时间（`picked_at`），以及点开了哪几朵的原文（`opened_at`）。仓库是公开的，这两个数也公开。

品种就是内容的类型：猴头菇＝慢读的长文，鸡枞＝新鲜事，竹荪＝好看的东西，松茸＝稀有的好东西（一周最多一朵），野蘑菇＝喂过的范围之外。
能不能吃：🍄能吃＝可靠来源、能多方核实；🟡先闻闻＝单一来源或观点性内容，自己判断。

## 上手（一次性，大约 15 分钟）

### 1. 填密钥

仓库 → **Settings → Secrets and variables → Actions → New repository secret**，按下表一个个加：

| 名字 | 填什么 | 什么时候需要 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 在 console.anthropic.com 生成的 key | 只有 `source: claude` 时才要，原型阶段不用 |
| `NTFY_TOPIC` | 自己编一个别人猜不到的名字，比如 `mogu-` 加一串随机字母；手机 ntfy App 里订阅同一个名字 | 用 ntfy 时；也决定回信箱的主题 |
| `FEEDBACK_TOPIC` | 回信箱主题，不填就用 `NTFY_TOPIC` 加 `-fb`。只用微信或邮件、不用 ntfy 推送时，填一个随机名字就能开回信箱（手机不用装 ntfy） | 可选 |
| `SERVERCHAN_KEY` | sct.ftqq.com 微信扫码登录后拿到的 SendKey | 用微信时 |
| `SMTP_HOST` | QQ 邮箱填 `smtp.qq.com`，Gmail 填 `smtp.gmail.com` | 用邮件时 |
| `SMTP_PORT` | `465` | 用邮件时 |
| `SMTP_USER` | 发信的邮箱地址 | 用邮件时 |
| `SMTP_PASS` | QQ 邮箱的「授权码」或 Gmail 的「应用专用密码」，不是登录密码 | 用邮件时 |
| `MAIL_TO` | 收信地址，可以就是自己 | 用邮件时 |

ntfy 的公共服务器上，知道主题名的人都能看到消息，所以主题名一定要编得长一点、随机一点。

### 2. 打开网页

仓库 → **Settings → Pages → Build and deployment**：Source 选 **Deploy from a branch**，分支选 `main`，文件夹选 `/docs`，保存。
过一两分钟会给出网址，一般是 `https://<你的用户名>.github.io/mogu-yuhou/`。把它填进 `config.yaml` 的 `page_url`，推送里的「打开篮子」就会跳到这个网页。

（免费账号只有公开仓库能开 Pages。私有仓库要 GitHub Pro，学生包里就有。）

### 3. 试一下

仓库 → **Actions → 下雨 → Run workflow**，选：

- **测试推送（发一朵测试蘑菇）**：检查三个渠道通不通，不算一场雨。
- **预演（照常挑蘑菇，不送不存）**：看看这一场会冒出哪几朵，日志里能看到。
- **求雨（现在就下一场）**：真的下一场，会送、会存、会用掉池子里的蘑菇。

如果收进仓库那一步报 `403`：Settings → Actions → General → Workflow permissions 选 **Read and write permissions**。

## 日常

- **等雨。**就这样。
- **反馈**：每朵蘑菇下面有「好吃 / 难吃 / 还想要 / 别再带」，点一下就记下，再点一下撤回。下一次看天时收进去，之后的雨会参考。
- **喂**：网页右下角的「喂一口」，先列出它吃过什么，再写新的。也可以开一个 Issue，标题写「喂 想看……」，或者直接改 `feed.yaml`。原型阶段蘑菇池是固定的，喂进去的东西会先记下来，等切到 `source: claude` 才真正影响采什么；在那之前，按喂的方向补池子。
- **补蘑菇**：网页底部会显示池子里还剩几朵。快见底了就往 `pool.yaml` 里加，格式照抄已有的。池子空了就不下雨。
- **调天气**：改 `config.yaml`，可以调时区、醒着的时段、一周几场、换模型。

求雨只是测试用的。如果发现自己老想去点它，这件事本身就值得记下来：等不及雨，正是「钓鱼模式」要冒头的时候。

## 花多少钱

- 原型阶段（`source: pool`）：零。
- 切到 `source: claude` 之后：每次搜索 $0.01，再加 token 费。用 Sonnet 5.5，一场雨大约 $0.1–0.2；换成 Haiku 5.5 更省。每场雨的估算都记在 `rains.json` 的 `cost_usd` 里。
- GitHub Actions：公开仓库免费。私有仓库每小时跑一次，大约用掉免费额度的三分之一。

## 已知的限制

- GitHub 的定时任务在高峰期会延迟，偶尔跳过某个小时。对「说不准什么时候下雨」来说没关系。
- 公开仓库 60 天没有提交，定时任务会被暂停。下雨会自动提交，一般碰不到。
- 蘑菇池是 2026-11-25 一次性采的，按一周 6 场雨算，大约够两周。
- 切到联网现采以后：中文网站，尤其公众号文章，搜索覆盖有限。
- 反馈要多点一次「提交」。做 App 的时候再改。

## 文件

```
config.yaml            天气设置
feed.yaml              喂过的、不要的
pool.yaml              蘑菇池（原型阶段的蘑菇都从这里来）
rain/weather.py        要不要下雨
rain/pool.py           从蘑菇池里挑蘑菇
rain/forage.py         联网采蘑菇、过筛子（source: claude 时用）
rain/notify.py         ntfy / 微信 / 邮件
rain/feedback.py       用 Issue 喂养和反馈（没有钥匙时的退路）
rain/relay.py          回信箱：把网页上的反馈、喂、采、点开拉回来
rain/main.py           每小时跑的入口
docs/index.html        网页：雨后采集笔记（思源宋体；五种蘑菇的细线插图是原创手绘的 SVG）
docs/data/             下过的雨、反馈
tests/                 测试：python -m pytest
```
